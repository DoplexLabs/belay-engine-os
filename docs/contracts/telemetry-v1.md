# Contract: Usage Telemetry V1

- **Status:** Implemented in Belay Local
- **Contract ID:** `belay.telemetry.v1`
- **Sender:** `internal/telemetry`, invoked at `belay local`, `belay quickstart`,
  and `belay mcp` start
- **Receiver:** `POST https://getbelay.vercel.app/api/telemetry`

## Principle

Doplex needs to know how many people install and keep using Belay. It does not
need to know who they are or what they work on. This contract fixes the entire
payload; adding a field is a contract change that must be reviewed against the
prohibited classes below.

## Events

| Event | When | Frequency |
|---|---|---|
| `install` | first successful send from a Belay home directory | once |
| `active` | any product start | at most once per UTC day |

## Payload

```json
{
  "schema_version": "belay.telemetry.v1",
  "event": "active",
  "telemetry_id": "8d4c1d1e-6f1a-4b8a-9c2d-3e5f7a9b1c2d",
  "version": "0.0.1-alpha.8",
  "os": "darwin",
  "arch": "arm64",
  "harnesses": ["claude"],
  "sent_at": "2026-09-15T10:00:00Z"
}
```

- `telemetry_id` is a random UUID generated by Belay and stored in
  `<home>/telemetry.json`. It is distinct from the local installation ID used
  inside the evidence store, is not derived from hardware, account, or OS
  identifiers, and changes if the state file is deleted.
- `harnesses` lists only which of `claude` and `codex` are on `PATH`.
- The receiver records the request's country from the CDN header and discards
  the address. It stores one record per event, day, and telemetry ID.

## Prohibited

Paths, project names, repository remotes, hostnames, usernames, prompts,
transcripts, tool output, session keys, issue or evidence identifiers, cost
figures, counts of anything the user did, and any hardware or account
identifier.

## Controls

- `belay telemetry status` prints the enabled state, the ID, and the field
  list; `belay telemetry off` opts out; `belay telemetry on` opts back in.
- `BELAY_TELEMETRY=0` (or `false`, `off`, `no`) disables sending.
- Builds whose version is `dev` send nothing unless
  `BELAY_TELEMETRY_ENDPOINT` is set explicitly for testing.
- Sending is fail-open with a five-second timeout; a failed send is retried on
  a later start and never affects product behavior.
